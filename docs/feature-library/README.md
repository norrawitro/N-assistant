# คลังฟีเจอร์ (feature library)

เอกสารนี้เก็บ "ชิ้นส่วน" ของแอปที่สร้างแล้ว แต่ละฟีเจอร์เขียนให้หยิบไปประกอบกับแอปอื่นได้โดยไม่ต้องคิดใหม่
(ใช้กับ N-assistant และ GPS-Tracker ที่มีโครงสร้างเดียวกัน)

## วิธีใช้ในแอปใหม่
1. เปิด `FEATURES.md` แล้วเลือกฟีเจอร์ที่ต้องการ
2. อ่านหัวข้อ **ไฟล์ต้นทาง** และ **ค่าที่ต้องปรับ** ของฟีเจอร์นั้น
3. คัดลอกไฟล์ต้นทางไปโปรเจกต์ใหม่ แล้วแก้ชื่อแพ็กเกจ, ชื่อหน้า และคีย์ที่เก็บในเครื่อง
4. อ่าน **ข้อควรระวัง** ก่อนทดสอบ เพราะเป็นสิ่งที่เคยพังมาแล้ว

## โครงสร้างแอปที่ใช้ร่วมกัน
- Android Java + WebView โหลด `assets/www/index.html`, `app.js`, `bot.js`, `kb.js`, `faq.js`
- ฝั่ง JS เรียก Java ผ่าน `window.Android` (ประกาศด้วย `@JavascriptInterface`)
- Java ส่งเหตุการณ์กลับหน้าเว็บด้วย `emit(ชื่อเหตุการณ์, JSON)` ซึ่งเรียก `window.__native(ชื่อ, ข้อมูล)`
- ข้อมูลของผู้ใช้เก็บใน `localStorage` (`docs`) และสำรองไปยัง `Documents/<ชื่อแอป>/` ผ่าน MediaStore
- คีย์ API เก็บแยกใน `localStorage` ไม่อยู่ในไฟล์สำรอง

## แม่แบบการเขียนฟีเจอร์ใหม่ (ให้ใช้ทุกครั้ง)
```
## ชื่อฟีเจอร์
- ทำอะไร: (หนึ่งบรรทัด)
- ไฟล์ต้นทาง: (พาธ + ชื่อคลาส/ฟังก์ชัน)
- ค่าที่ต้องปรับ: (ค่าคงที่ที่ควรจูนกับเครื่องจริง)
- วิธีทำงาน: (ขั้นตอนสั้นๆ)
- ข้อควรระวัง: (สิ่งที่เคยพังหรือ Android จำกัด)
- ทดสอบอะไร: (ทดสอบในเบราว์เซอร์ / บนมือถือ / ยังไม่ได้ทดสอบ)
- เวอร์ชันที่ออก: (เลข release)
```

## กฎการบันทึก
- เมื่อสร้างหรือแก้ฟีเจอร์ ให้เพิ่มหรือแก้บล็อกใน `FEATURES.md` ในรอบเดียวกัน
- เขียนชื่อคีย์ ค่าคงที่ และพาธ แต่ **ห้าม** ใส่คีย์ API โทเคน หรือข้อมูลส่วนตัวของผู้ใช้
